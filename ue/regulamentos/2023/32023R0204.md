# Regulamento de Execução (UE) 2023/204 da Comissão de 28 de outubro de 2022 que estabelece as especificações técnicas, as normas e os procedimentos com vista a estabelecer um ambiente europeu de plataforma única para o setor marítimo nos termos do Regulamento (UE) 2019/1239 do Parlamento Europeu e do Conselho (Texto relevante para efeitos do EEE)

**Texto:** versão original publicada no Jornal Oficial (sem alterações posteriores, se as houver).

## Preâmbulo

A COMISSÃO EUROPEIA,

Tendo em conta o Tratado sobre o Funcionamento da União Europeia,

Tendo em conta o Regulamento (UE) 2019/1239 do Parlamento Europeu e do Conselho, de 20 de junho de 2019, que estabelece um ambiente europeu de plataforma única para o setor marítimo e que revoga a Diretiva 2010/65/UE [^1], nomeadamente o artigo 5.º, n.º 10, o artigo 6.º, n.º 4, o artigo 11.º, n.º 3, o artigo 14.º, n.º 4, o artigo 15.º, n.º 4, e o artigo 16.º, n.º 6,

Após consulta do Comité de Facilitação Digital dos Transportes e do Comércio,

Considerando o seguinte:

- (1) As plataformas nacionais únicas para o setor marítimo devem proporcionar aos declarantes as interfaces gráficas do utilizador com todas as funcionalidades necessárias para dar cumprimento às obrigações de declaração enumeradas no anexo do Regulamento (UE) 2019/1239. A fim de assegurar uma experiência de utilizador equiparável, deve ser definida uma lista comum de funcionalidades e essas funcionalidades devem estar disponíveis para os declarantes em todos os Estados-Membros. No entanto, para minimizar os custos e assegurar a compatibilidade com as interfaces existentes, os Estados-Membros podem oferecer funcionalidades adicionais na sua interface gráfica do utilizador.

- (2) As folhas de cálculo digitais são amplamente utilizadas no setor marítimo. Ajudam os declarantes a introduzir dados manualmente e a cumprir as suas obrigações em matéria de comunicação de informações. A fim de assegurar que os declarantes possam reutilizar os modelos das folhas de cálculo em diferentes plataformas nacionais únicas para o setor marítimo, as características das folhas de cálculo devem ser harmonizadas e as versões das folhas de cálculo devem ser geridas centralmente pela Comissão. Além disso, quando os modelos de folhas de cálculo são conformes com as características harmonizadas e os requisitos do conjunto de dados do EMSWe, devem ser aceites por todas as interfaces gráficas de utilizador, independentemente da língua utilizada.

- (3) As especificações técnicas para disponibilizar os horários de chegada e de partida dos navios devem abranger tanto a comunicação entre o utilizador e o sistema como a comunicação entre sistemas, o que permitirá aos utilizadores ao longo da cadeia logística beneficiar dos horários de chegada e de partida dos navios (publicados em formato eletrónico) e garantir a harmonização a nível da UE.

- (4) Deve ser definida uma estrutura comum para os sítios Web de apoio, incluindo as suas funcionalidades. Tal assegurará uma experiência de utilizador equiparável em todas as plataformas nacionais únicas para o setor marítimo. Uma estrutura comum ajudará igualmente a fornecer o apoio e a informação adequados sobre os processos e os requisitos técnicos aplicáveis às plataformas nacionais únicas para o setor marítimo e respetivas interfaces.

- (5) Os endereços Internet das plataformas nacionais únicas para o setor marítimo devem utilizar um formato comum de domínios e subdomínios que seja sustentável, para ajudar os utilizadores a navegar, tendo em conta os endereços Internet existentes utilizados nos Estados-Membros. A fim de facilitar a acessibilidade das plataformas nacionais únicas para o setor marítimo, a Comissão, em colaboração com os Estados-Membros, deverá estabelecer e manter uma lista de endereços Internet.

- (6) Com o objetivo de assegurar o bom funcionamento e a rápida disponibilidade da base de dados de navios do EMSWe, da base de dados comum de localizações e da base de dados comum de materiais perigosos, devem ser definidas medidas de segurança do sistema e requisitos mínimos de desempenho do sistema.

- (7) A fim de assegurar que as informações e os elementos de identificação dos navios possam ser recolhidos, armazenados, atualizados e disponibilizados rapidamente, a base de dados de navios do EMSWe deverá poder comunicar com as plataformas nacionais únicas para o setor marítimo, utilizando a comunicação entre sistemas e entre utilizadores e sistemas. Qualquer alteração das informações e dos elementos de identificação dos navios, com base nos dados apresentados pelos declarantes nas plataformas nacionais únicas para o setor marítimo, deverá ser refletida na base de dados dos navios do EMSWe.

- (8) As isenções de declaração de navios são concedidas pelas autoridades competentes e não são solicitadas aos declarantes durante uma escala portuária. Uma vez que estas informações já estão disponíveis no sistema SafeSeaNet [^2], a base de dados de navios do EMSWe deve poder ligar-se à mesma, obter essas informações automaticamente e disponibilizá-las às plataformas nacionais únicas para o setor marítimo.

- (9) A fim de garantir que os códigos das localizações e os códigos das instalações portuárias possam ser recolhidos, armazenados, atualizados e disponibilizados rapidamente, a base de dados comum de localizações deverá poder enviar informações para as plataformas nacionais únicas para o setor marítimo, utilizando a comunicação entre sistemas e entre utilizadores e sistemas. A base de dados comum de localizações deve ser sincronizada com outras fontes de informação relevantes.

- (10) A fim de assegurar que as informações de referência sobre os materiais perigosos possam ser recolhidas, armazenadas, atualizadas e disponibilizadas rapidamente, a base de dados comum de materiais perigosos deve poder enviar informações para as plataformas nacionais únicas para o setor marítimo, utilizando a comunicação entre sistemas e entre utilizadores e sistemas. A base de dados comum de materiais perigosos deve ser sincronizada com outras fontes de informação relevantes, incluindo a base de dados MAR-CIS [^3] desenvolvida pela Agência Europeia da Segurança Marítima (AESM).

- (11) A AESM deverá assistir a Comissão na criação da base de dados de navios do EMSWe, da base de dados comum de localização e da base de dados comum de materiais perigosos, tendo em conta as sinergias com as bases de dados existentes geridas pela AESM e o seu objetivo de contribuir para a eficiência global do transporte marítimo, tal como definido no Regulamento (CE) n.º 1406/2002 do Parlamento Europeu e do Conselho [^4].

- (12) O Regulamento EMSWe habilita a Comissão a adotar atos de execução para estabelecer uma lista de informações pertinentes na declaração sumária de entrada a que se refere o artigo 127.º do Regulamento (UE) n.º 952/2013 do Parlamento Europeu e do Conselho [^5], a disponibilizar às plataformas nacionais únicas para o setor marítimo. Uma vez que o Regulamento EMSWe se limita especificamente ao domínio marítimo, só devem ser consideradas pertinentes as declarações sumárias de entrada definidas nas colunas F10, F11, F12 e F13 do anexo B do Regulamento Delegado (UE) 2015/2446 da Comissão [^6] apresentadas pelos transportadores marítimos ou pelos seus representantes no cabeçalho da declaração e a nível da remessa master, incluindo os elementos informativos relativos à adição de mercadorias da remessa master. Isto significa que as declarações sumárias de entrada apresentadas por outros intervenientes que não os acima mencionados ou as informações a nível da remessa house não devem ser consideradas pertinentes.

- (13) As informações constantes da declaração sumária de entrada a disponibilizar às plataformas nacionais únicas para o setor marítimo só devem provir dos documentos comerciais e de transporte, emitidos pelo transportador marítimo, que podem ser solicitados no âmbito de outras obrigações de declaração relacionadas com essa escala portuária. A fim de assegurar a interoperabilidade dos dados trocados, estas informações devem ser afetadas aos elementos de dados do conjunto de dados do EMSWe previsto no artigo 3.º, n.º 1, do Regulamento (UE) 2019/1239.

- (14) Uma vez que o Regulamento (UE) 2019/1239 é aplicável a partir de 15 de agosto de 2025, o presente regulamento deverá aplicar-se a partir da mesma data,

ADOTOU O PRESENTE REGULAMENTO:

## Texto

### Artigo 1.º — Definições

Para efeitos do presente regulamento, são aplicáveis as definições constantes do artigo 2.º do Regulamento (UE) 2019/1239. São igualmente aplicáveis as seguintes definições:

- — «formalidade», um conjunto coerente de elementos de dados a comunicar por um declarante à plataforma nacional única para o setor marítimo, a fim de cumprir uma ou mais obrigações de declaração;

- — «interface de gestão da área de trabalho do utilizador», uma área da interface gráfica do utilizador da plataforma nacional única para o setor marítimo que exige que uma pessoa singular efetue a autenticação introduzindo credenciais de início de sessão;

- — «folha de cálculo», um documento eletrónico em que os dados estão dispostos em linhas e em colunas e que pode ser manipulado e utilizado nos cálculos;

- — «ficheiro da folha de cálculo», um ficheiro eletrónico que contém uma ou mais folhas de cálculo;

- — «célula de dados», a intersecção de uma linha com uma coluna numa folha de cálculo com um endereço único constituído pela letra da coluna e o número da linha para efeitos de introdução de dados;

- — «registo do navio», um conjunto de elementos de dados sobre o mesmo navio armazenados na base de dados de navios do EMSWe.

### Artigo 2.º — Disposições relativas às interfaces harmonizadas

As funcionalidades comuns da interface gráfica de utilizador e o conteúdo dos modelos harmonizados de folha de cálculo digital a que se refere o artigo 6.º, n.º 4, do Regulamento (UE) 2019/1239 constam do anexo I do presente regulamento.

### Artigo 3.º — Disposições relativas às plataformas nacionais únicas para o setor marítimo

As especificações técnicas relativas à disponibilização dos horários de chegada e de partida a que se refere o artigo 5.º, n.º 10, do Regulamento (UE) 2019/1239 constam do anexo II do presente regulamento.

A estrutura harmonizada do sítio Web de apoio a que se refere o artigo 5.º, n.º 10, do Regulamento (UE) 2019/1239 consta do anexo III do presente regulamento.

O modelo uniforme para os endereços Internet a que se refere o artigo 5.º, n.º 10, do Regulamento (UE) 2019/1239 consta do anexo IV do presente regulamento.

### Artigo 4.º — Outros serviços comuns

As especificações técnicas, as normas e os procedimentos para a criação da base de dados dos navios do EMSWe a que se refere o artigo 14.º, n.º 4, do Regulamento (UE) 2019/1239, no que diz respeito à recolha, ao armazenamento, à atualização e ao fornecimento de informações e dados de identificação dos navios, bem como aos registos das isenções de declaração de navios, constam do anexo V do presente regulamento.

As especificações técnicas, as normas e os procedimentos para a criação da base de dados comum de localizações referida no artigo 15.º, n.º 4, do Regulamento (UE) 2019/1239 no que diz respeito à recolha, ao armazenamento e fornecimento dos códigos das localizações e das instalações portuárias constam do anexo VI do presente regulamento.

As especificações técnicas, as normas e os procedimentos para a criação da base de dados comum de materiais perigosos referida no artigo 16.º, n.º 6, do Regulamento (UE) 2019/1239 no que diz respeito à recolha, ao armazenamento e fornecimento de informações de referência sobre os materiais perigosos constam do anexo VII do presente regulamento.

### Artigo 5.º — Lista de informações pertinentes na declaração sumária de entrada

As informações da declaração sumária de entrada enumeradas no anexo VIII do presente regulamento limitam-se aos elementos da declaração sumária de entrada definidos nas colunas F10, F11, F12 e F13 do anexo B do Regulamento (UE) 2015/2446 ao nível do cabeçalho da declaração e da remessa master, incluindo as informações relativas às mercadorias da remessa master, que são apresentadas diretamente pelo transportador marítimo ou pelo seu representante. As restantes informações da declaração sumária de entrada não devem ser disponibilizadas à plataforma nacional única para o setor marítimo.

A lista das informações pertinentes constantes da declaração sumária de entrada a que se refere o artigo 127.º do Regulamento (UE) n.º 952/2013 a disponibilizar para a plataforma nacional única para o setor marítimo em conformidade com o artigo 11.º, n.º 3, do Regulamento (UE) 2019/1239 consta do anexo VIII do presente regulamento.

### Artigo 6.º — Entrada em vigor e aplicação

O presente regulamento entra em vigor no dia seguinte ao da sua publicação no Jornal Oficial da União Europeia.

A presente decisão é aplicável a partir de 15 de agosto de 2025.

O presente regulamento é obrigatório em todos os seus elementos e diretamente aplicável em todos os Estados-Membros.

Feito em Bruxelas, em 28 de outubro de 2022.

## ANEXO I — FUNCIONALIDADES COMUNS DA INTERFACE GRÁFICA DO UTILIZADOR E CONTEÚDO DOS MODELOS DAS FOLHAS DE CÁLCULO DIGITAIS HARMONIZADAS

A interface gráfica do utilizador da plataforma nacional única para o setor marítimo deve prever uma «página de acesso» e um « user desktop ».

A página «de acesso» deve estar acessível ao público e incluir:

- — informações sobre as plataformas nacionais únicas para o setor marítimo;

  - — uma ligação ao sítio Web de apoio em linha e às horas estimadas e efetivas de chegada e partida dos navios;

  - — uma secção de início de sessão para a autenticação do utilizador com vista a aceder à interface de gestão da área de trabalho destinada ao utilizador (« user desktop» ).

Após a autenticação bem sucedida, a interface de gestão da área de trabalho destinada ao utilizador deve ser disponibilizada aos declarantes com as seguintes funcionalidades comuns:

| Lista dos navios <br> Esta funcionalidade deve permitir a consulta: <br> — da lista dos navios aquando da criação de uma nova escala portuária; <br> — das informações e dos elementos de identificação do navio, incluindo isenções de declaração de navios, a disponibilizar na base de dados de navios do EMSWe (ambiente europeu de plataforma única para o setor marítimo) ou, em alternativa, noutra base de dados pertinente. <br> Deve ser fornecido um filtro para pesquisar a lista de acordo com os seguintes critérios: <br> — número OMI do navio, <br> — indicativo de chamada do navio, <br> — número MMSI, <br> — nome do navio. |
|---|
| Lista das escalas portuárias <br> A lista de escalas portuárias deve estar acessível durante um determinado período, conforme especificado nas regras nacionais de conservação de dados. Devem estar disponíveis, pelo menos, as seguintes informações: porto de escala, documento de identificação da visita, identificação do navio, horas de chegada e de partida, estimadas e reais, dos navios. Em conformidade com estes critérios, deve ser fornecido um filtro para pesquisar a lista. |
| Panorâmica das escalas portuárias <br> A escala portuária selecionada deve conter informações sobre o estado das formalidades e as respostas das autoridades relacionadas com essa escala, incluindo o modelo de autorização (sistemático ou silencioso) aplicado pela plataforma nacional única para o setor marítimo. |
| Criação de uma escala portuária <br> Esta funcionalidade deve permitir criar uma escala portuária selecionando um navio a partir da funcionalidade «lista de navios» ou preenchendo manualmente as informações de identificação do navio e o porto de escala a partir das informações extraídas da plataforma nacional única para o setor marítimo da base de dados comum de localização. Aquando da criação da escala portuária, deve ser fornecido um documento de identificação da visita associado ao navio selecionado e ao porto de escala. |
| Criação de uma nova formalidade <br> Esta funcionalidade deve permitir que os declarantes forneçam uma nova formalidade para a escala portuária selecionada a partir da lista de escalas portuárias. <br> Caso as informações de identificação e os dados ou registos de identificação de um navio sobre as isenções de declaração sejam necessários para o cumprimento das obrigações de declaração, a plataforma nacional única para o setor marítimo deverá disponibilizar as informações pertinentes da base de dados de navios do EMSWe ou, em alternativa, de outra base de dados pertinente na interface gráfica de utilizador, através do pré-preenchimento dos campos pertinentes. <br> Caso seja necessário um código de localização ou de instalação portuária para o cumprimento das obrigações de declaração, a plataforma nacional única para o setor marítimo disponibilizará as informações pertinentes da base de dados comum de localização na interface gráfica do utilizador. <br> Caso sejam necessárias informações sobre mercadorias perigosas e poluentes para o cumprimento das obrigações de declaração, a plataforma nacional única para o setor marítimo disponibilizará as informações pertinentes da base de dados comum Hazmat na interface gráfica do utilizador através do: <br> — pré-preenchimento das informações exigidas sobre mercadorias perigosas e poluentes com base no número ONU ou na referência textual de um elemento DPG inscrito pelo declarante; <br> — fornecimento de uma lista de mercadorias perigosas e poluentes com base no modo de transporte e no tipo de produto indicado pelo declarante. |
| Carregamento das informações das folhas de cálculo <br> Ao fornecer ou atualizar uma ou mais formalidades, os declarantes devem poder carregar as informações das folhas de cálculo digitais. <br> As plataformas nacionais únicas para o setor marítimo devem assegurar que a versão do modelo de folha de cálculo está em conformidade com a última versão disponível ou, durante o período de transição durante o qual é emitida uma nova versão dos modelos, com uma das duas últimas versões consecutivas dos modelos da folha de cálculo. Consequentemente, uma versão dos modelos será gradualmente eliminada na data de termo do período de transição. <br> Após o carregamento do ficheiro da folha de cálculo, a plataforma nacional única para o setor marítimo verificará se o formato, a cardinalidade e as regras comerciais dos elementos de dados estão em conformidade com os definidos no conjunto de dados do EMSWe. <br> Se a folha de cálculo não cumprir as regras relativas às versões ou os requisitos do conjunto de dados do EMSWe, a plataforma nacional única para o setor marítimo rejeitará as informações da folha de cálculo e fornecerá uma mensagem de erro com uma indicação clara das razões para a falha da verificação. <br> Após a aprovação nos controlos das plataformas nacionais únicas para o setor marítimo, os elementos de dados extraídos da folha de cálculo substituirão os elementos de dados previamente preenchidos na interface gráfica de utilizador. Antes da apresentação, a interface gráfica de utilizador deve proporcionar a possibilidade de ler, rever e corrigir as informações extraídas dessa folha de cálculo. |
| Reutilização das formalidades existentes <br> Ao prepararem novas formalidades para uma escala portuária, os declarantes devem poder reutilizar o conteúdo disponível das formalidades relativas ao mesmo navio que tenham previamente apresentado na mesma plataforma nacional única para o setor marítimo. |
| Guardar projetos de formalidades <br> Os declarantes devem poder guardar os projetos de formalidades antes da apresentação. |
| Apresentação das formalidades <br> Os declarantes devem poder apresentar formalidades às plataformas nacionais únicas para o setor marítimo. Após a apresentação das informações, a plataforma nacional única para o setor marítimo deve apresentar os resultados dos controlos semânticos efetuados a nível do Estado-Membro. |
| Gestão das formalidades <br> Esta funcionalidade deve permitir que os declarantes consultem e atualizem as formalidades previamente apresentadas ou os projetos de formalidades. Quando autorizados, devem poder retirar ou invalidar as suas formalidades individuais. <br> Todas as formalidades que tenham sido apresentadas utilizando o módulo de interface de declaração harmonizado devem também estar disponíveis na interface gráfica do utilizador. A interface gráfica do utilizador deve apresentar informações (data e hora de apresentação) de todas essas formalidades, incluindo as respostas das autoridades. |
| Cancelamento de uma escala portuária <br> Os declarantes devem poder cancelar a sua escala portuária previamente criada e retirar ou anular as formalidades previamente apresentadas associadas a essa escala. |
| Configuração de dados pessoais <br> Os declarantes devem poder configurar informações pessoais adicionais estabelecidas a nível nacional que não sejam geridas pelo sistema de gestão do registo e do acesso de utilizadores do EMSWe. |

A interface gráfica do utilizador da plataforma nacional única para o setor marítimo deve permitir que os declarantes selecionem a versão linguística da interface gráfica do utilizador. A língua inglesa deve estar sempre disponível.

Os Estados-Membros podem disponibilizar funcionalidades adicionais na sua interface gráfica do utilizador.

#### Conteúdo dos modelos de folha de cálculo

A Comissão elabora e disponibiliza os seguintes tipos de modelos de folhas de cálculo:

- — notificação prévia de chegada,

- — notificação prévia de partida,

- — notificação prévia de chegada de navios sujeitos a inspeção alargada,

- — notificação de segurança,

- — notificação de resíduos,

- — recibo de entrega de resíduos,

- — lista da tripulação e dos bens da tripulação,

- — lista de passageiros,

- — provisões a bordo,

- — declaração geral de carga,

- — mercadorias perigosas ou poluentes,

- — declaração marítima de saúde,

- — itinerário do navio de cruzeiro,

- — informações sobre o abastecimento de combustível.

Os modelos da folha de cálculo devem respeitar os nomes, os formatos e as regras comerciais dos elementos do conjunto de dados do EMSWe.

Os modelos das folhas de cálculo devem ser disponibilizados em conjunto, sendo-lhes atribuído um número de versão que deverá ser indicado na folha de cálculo. Cada versão do conjunto de modelos das folhas de cálculo corresponde a uma versão do conjunto de dados do EMSWe.

Cada célula de dados ou grupo de células de dados deve ser associada a um elemento do conjunto de dados do EMSWe e identificada com um código, um formato e um nome (uma rubrica) em língua inglesa. Os Estados-Membros podem traduzir os modelos das folhas de cálculo com rubricas para outras línguas que não o inglês. Os valores contidos nas células que não sejam concebidos para entrada não devem ser alterados.

Os modelos de folha de cálculo devem incluir o controlo básico dos dados sobre os valores das células de dados. O modelo da folha de cálculo deve permitir copiar e colar o conteúdo de e para as células de dados.

Sempre que a célula de dados exija um valor de uma lista de códigos, se for caso disso, esse valor deverá ser selecionável a partir de uma lista deslizante.

Sempre que os elementos de dados devam ser comunicados em vários registos, a primeira coluna deverá indicar o número sequencial de cada registo.

Cada modelo de folha de cálculo deverá incluir a indicação do seu tipo.

O formato da folha de cálculo deverá ser codificado em formato de ficheiro Office Open XML (extensão «XLSX»). O ficheiro da folha de cálculo deverá incluir apenas características que sejam suportadas pelas especificações oficiais do Office Open XML. O ficheiro da folha de cálculo não deve conter carateres nem códigos executáveis.

A interface gráfica de utilizador da plataforma nacional única para o setor marítimo deve oferecer a possibilidade de comunicar todas as folhas de cálculo necessárias num ficheiro de folha de cálculo ou de comunicar uma folha de cálculo individual por ficheiro da folha de cálculo.

## ANEXO II — ESPECIFICAÇÕES TÉCNICAS PARA A DISPONIBILIZAÇÃO AO PÚBLICO DAS HORAS DE CHEGADA E DE PARTIDA

#### 1. Requisitos da interface

Os Estados-Membros devem disponibilizar ao público as horas estimadas e efetivas de chegada e de partida dos navios num sítio Web acessível a partir da interface gráfica do utilizador da plataforma nacional única para o setor marítimo, num formato legível e num formato sistema a sistema.

#### 2. Conjunto de dados a disponibilizar ao público

As horas de chegada e de partida dos navios devem incluir as seguintes categorias e o seguinte conjunto mínimo de dados:

| Categoria | Informações a prestar |
|---|---|
| Informação sobre o navio | Número OMI do navio <br> Nome do navio |
| Informações sobre a viagem | Porto de escala, codificado <br> Data e hora de chegada – estimativa em hora local <br> Data e hora de partida – estimativa em hora local |
| Dados da notificação de chegada | Data e hora de chegada – efetiva em hora local |
| Dados da notificação de partida | Data e hora de partida – efetiva em hora local |
| Estado de escala portuária | Situação da escala portuária (com valores: chegada prevista, chegada, partida, anulação) |

Os Estados-Membros podem fornecer informações adicionais relativas ao conjunto mínimo de elementos de dados acima enumerados.

Se uma determinada informação ainda não se encontrar disponível, o campo de dados correspondente poderá ser deixado em branco.

Os Estados-Membros determinam o prazo durante o qual as informações sobre as horas de chegada e de partida dos navios devem ser disponibilizadas ao público.

Os Estados-Membros podem acrescentar declarações de exoneração de responsabilidade relativamente às horas de chegada e de partida publicadas, a fim de clarificar a fonte, a atualidade ou a finalidade da hora disponível, estimada ou efetiva, dos navios.

Nos termos do artigo 5.º, n.º 8, do Regulamento (UE) 2019/1239, as disposições relativas ao conjunto de dados a disponibilizar ao público não se aplicam aos navios que transportem carga sensível.

#### 3. Especificações para a interação entre o utilizador e o sistema

O sítio Web sobre os horários de chegada e de partida dos navios deve incluir as seguintes categorias de dados e fornecer as seguintes funcionalidades:

#### 3.1. Função de pesquisa

Deve estar disponível um motor de pesquisa, que deverá incluir os seguintes filtros, a fim de limitar os resultados apresentados:

- — Porto de escala – selecionar a partir de uma lista predefinida ou inserir num campo de entrada;

- — Intervalo de tempo da data – selecionar entre uma série de horas de datas;

- — Nome do navio – inserir num campo de entrada;

- — Número OMI do navio – inserir num campo de entrada;

- — Estado de escala do porto – selecionar a partir de uma lista de valores predefinidos.

Os Estados-Membros podem optar por incluir filtros adicionais no motor de pesquisa.

#### 3.2. Triagem de colunas

Para as listas de chegada e de partida, deve estar disponível uma funcionalidade de triagem de colunas em função das categorias de dados definidas no ponto 2. Para a triagem, tanto a ordem alfabética como a hora da data devem estar disponíveis por ordem ascendente e descendente. Por defeito, as listas devem ser ordenadas por hora de chegada ou partida por ordem ascendente (estimada ou efetiva – que será sempre a atual).

#### 4. Interação entre sistemas

A interação entre sistemas deve basear-se numa API HTTP RESTful Web com uma capacidade de carga útil em formato JSON.

#### 5. Requisitos não funcionais

#### 5.1. Conceção Web

As páginas Web das horas de chegada e de partida acessíveis ao público devem adotar a sua configuração e aparência para acomodar diferentes tamanhos de ecrã e janelas de visualização. As mensagens de «não suporte» devem ser apresentadas se for utilizado um navegador não compatível.

#### 5.2. Línguas

As horas de chegada e de partida dos navios devem ser disponibilizadas ao público nas línguas utilizadas pela interface gráfica do utilizador da plataforma nacional única para o setor marítimo.

## ANEXO III — ESTRUTURA HARMONIZADA PARA O SÍTIO DE APOIO DA PLATAFORMA NACIONAL ÚNICA PARA O SETOR MARÍTIMO

#### 1. Funcionalidades comuns do sítio Web de apoio em linha

O sítio Web de apoio em linha da plataforma nacional única para o setor marítimo deve incluir o seguinte conjunto de funcionalidades comuns:

#### 1.1. Seleção da língua

Os utilizadores devem poder mudar a língua em qualquer página do diagrama do sítio Web de apoio. Todos os conteúdos, com exceção das referências à legislação nacional e regional relativa às obrigações de comunicação de informações e a outras informações provenientes de fontes externas, devem estar disponíveis de forma a permitir ao utilizador selecionar a língua.

#### 1.2. Função de pesquisa

O sítio Web de apoio deve prever uma função de pesquisa de quaisquer informações pertinentes nele disponíveis.

#### 2. Estrutura de informação do sítio Web de apoio em linha

O sítio Web de apoio das plataformas nacionais únicas para o setor marítimo deve incluir informações sobre a utilização das plataformas nacionais únicas para o setor marítimo. Essas informações devem ser apresentadas de acordo com a seguinte estrutura:

- Página principal do sítio Web de apoio : deve conter informações introdutórias sobre a plataforma nacional única para o setor marítimo e um menu com as ligações para as seguintes secções:

- Orientações sobre a utilização de MNSW: esta secção deve fornecer instruções e orientações sobre os canais de comunicação disponíveis para uma escala portuária, incluindo as seguintes orientações de utilização:

  - — Utilização da interface gráfica de utilizador, incluindo as condições de utilização (informações sobre o processo de registo), manuais e ligações para outras fontes de informação pertinentes e folhas de cálculo digitais harmonizadas, bem como uma explicação sobre a sua utilização;

  - — Utilização do módulo de interface de comunicação, incluindo as condições de utilização (informações sobre o processo de registo), informações não sensíveis sobre as mensagens exigidas e, no mínimo, informações sobre onde obter mais informações sobre os processos de envio de mensagens;

  - — Utilização de outros canais de comunicação – incluindo orientações e informações sobre outros canais de comunicação, se os houver, os portos em que estão disponíveis outros canais de comunicação e ligações para as informações pertinentes desses outros canais de comunicação, tais como os sistemas de comunidades portuárias.

- Perguntas mais frequentes: esta secção fornece informações aos utilizadores sobre serviços, informações comerciais ou para obter assistência na resolução de problemas identificados. Esta secção deve satisfazer os seguintes requisitos:

  - — As perguntas encontram-se subdivididas por domínios temáticos;

  - — Deve ser dada uma resposta a cada pergunta;

  - — Se for caso disso, as respostas às perguntas devem incluir também ligações para outras perguntas, recursos ou ficheiros conexos.

- Dados de contacto das autoridades: esta secção deve fornecer os dados de contacto das autoridades envolvidas nos processos de escala portuária ou nas portas de acesso:

  - — Nome da autoridade e breve descrição das suas competências e responsabilidades;

  - — Sítio Internet.

- Contactos do serviço de assistência MNSW: Esta secção deve fornecer os dados de contacto do ponto de apoio do serviço de assistência nacional ao utilizador, para possa ser prestada ajuda, sob a forma de endereços de correio eletrónico, números de telefone ou formulários Web.

- Legislação nacional relevante: A presente secção contém referências à legislação nacional e local aplicável e a outros requisitos que estabelecem as obrigações de declaração durante as escalas portuárias no Estado-Membro.

#### 3. Acessibilidade

O sítio Web de apoio em linha da plataforma nacional única para o setor marítimo deve estar acessível ao público com o seu próprio endereço Internet. A página de entrada da interface gráfica de utilizador da plataforma nacional única para o setor marítimo deve indicar a ligação para esse endereço Internet.

## ANEXO IV — FORMATO UNIFORME PARA OS ENDEREÇOS INTERNET

O endereço Internet de cada plataforma nacional única para o setor marítimo é composto por um domínio de topo específico por país (ccTLD), por um domínio de segundo nível restrito a nível nacional {xyz}, por um lado, e por um nome de domínio de terceiro nível harmonizado, « mnsw », por outro, composto pelo seguinte formato uniforme:

mnsw.{xyz}.{ccTLD}

Os utilizadores podem ser reencaminhados a partir de mnsw.{xyz}.{ccTLD} para outros endereços Internet das plataformas nacionais únicas para o setor marítimo, utilizando um formato diferente do definido no presente anexo.

Os utilizadores que acedam a mnsw.{xyz}.{ccTLD} através do navegador Web devem ser reencaminhados para a página de entrada da interface gráfica de utilizador dessa plataforma nacional única para o setor marítimo.

Cada módulo de interface de comunicação harmonizado da plataforma nacional única para o setor marítimo deve utilizar o seguinte formato de endereço Internet:

rim.mnsw.{xyz}.{ccTLD}

O sítio Web de apoio em linha referido no anexo III e o sítio Web relativo às horas de chegada e de partida dos navios a que se refere o anexo II devem respeitar o seguinte formato de endereço Internet:

- Sítio Web de apoio em linha: mnsw.{xyz}.{ccTLD}/info

- Sítio Web para os horários de chegada e partida dos navios: mnsw.{xyz}.{ccTLD}/arrivals_departures

## ANEXO V — ESPECIFICAÇÕES TÉCNICAS, NORMAS E PROCEDIMENTOS PARA A CRIAÇÃO DA BASE DE DADOS DE NAVIOS DO EMSWE

#### 1. Síntese da base de dados de navios do EMSWe

A base de dados dos navios do EMSWe deve permitir a recolha, o armazenamento, a atualização e o fornecimento dos seguintes dados:

- — informações e elementos de identificação do navio, compostos por elementos do conjunto de dados do EMSWe relativos a um navio, estáticos ou sujeitos a alterações limitadas ao longo do tempo;

- — informações relativas às isenções de declaração de navios concedidas pelos Estados-Membros e notificadas no sistema de intercâmbio de informações marítimas da União (SafeSeaNet) referido na Diretiva 2002/59/CE.

A fim de assegurar o bom funcionamento e a disponibilidade das informações, a base de dados de navios do EMSWe deverá respeitar os requisitos mínimos de desempenho do sistema enumerados no ponto 4 e as medidas mínimas de segurança do sistema enumeradas no ponto 5.

A Comissão, assistida pela Agência Europeia da Segurança Marítima, deve:

- — assegurar a criação da base de dados de navios do EMSWe, das suas interfaces e dos seus serviços, bem como a gestão dos utilizadores;

- — assegurar que as plataformas nacionais únicas para o setor marítimo possam estabelecer a ligação com a base de dados de navios do EMSWe;

- — coordenar a execução dos ensaios de aceitação;

- — assegurar que a documentação operacional e técnica da base de dados de navios do EMSWe seja disponibilizada aos coordenadores nacionais e atualizada.

#### 2. Interfaces e serviços da base de dados de navios do EMSWe

A fim de trocar informações e dados de identificação dos navios e isenções de declaração de navios, a base de dados de navios do EMSWe deve fornecer a interface sistema a sistema e a interface Web tal como descritas nos pontos 2.1 e 2.2.

A Comissão, em consulta com os coordenadores nacionais, publica um Guia da Interface de Sistemas (SIG) que define o sistema de mensagens do sistema, as medidas e os procedimentos para estabelecer a ligação com a base de dados de navios do EMSWe, incluindo as políticas em matéria de direitos de acesso dos utilizadores e o processo de registo dos utilizadores.

#### 2.1. Interface sistema a sistema

|  | 1) | A interface sistema a sistema deve estar disponível para as plataformas nacionais únicas para o setor marítimo com vista ao intercâmbio automático de informações, utilizando um conjunto de mensagens predefinidas. A interface sistema a sistema deve suportar o serviço de anúncio e o serviço de notificação de informações sobre o navio descritos nos pontos 2.1.1 e 2.1.2. |
|---|---|---|

|  | 2) | Os Estados-Membros devem estabelecer e manter um sistema de ligação ao sistema entre a plataforma nacional única para o setor marítimo e a base de dados de navios do EMSWe, em conformidade com o Guia da Interface do Sistema. |
|---|---|---|

#### 2.1.1. Serviço de anúncio

A base de dados de navios do EMSWe deve utilizar o serviço de anúncio para distribuir às plataformas nacionais únicas para o setor marítimo que já tenham subscrito o serviço os dados mais recentes aquando de cada alteração (criação, atualização ou supressão) das informações e dos elementos de identificação dos navios, bem como das isenções de declaração dos navios. A lista completa das informações, dos elementos de identificação dos navios e das isenções de declaração dos navios deve ser distribuída à plataforma nacional única para o setor marítimo aquando da subscrição do serviço.

#### 2.1.2. Serviço de Notificação de Informações sobre Navios

O serviço de notificação de informações sobre navios é utilizado pelas plataformas nacionais únicas para o setor marítimo para fornecer à base de dados de navios do EMSWe as informações e os elementos de identificação do navio com base nos dados apresentados pelos declarantes no cumprimento das obrigações de declaração.

Em alternativa ao serviço de notificação de informações sobre navios, as informações e os elementos de identificação do navio podem ser fornecidos à base de dados de navios do EMSWe através do SafeSeaNet, desde que o SafeSeaNet permita o intercâmbio dessas informações.

#### 2.2. Interface Web

A interface Web deve ser acessível aos utilizadores autorizados para:

- — consultar o conteúdo da base de dados de navios do EMSWe;

- — descarregar informações sobre os navios com base em diferentes critérios e em diferentes formatos.

O acesso à interface Web da base de dados de navios do EMSWe deve ser facultado aos coordenadores nacionais, mediante pedido.

#### 3. Procedimentos de atualização das informações da base de dados de navios do EMSWe

Deve ser adotado o procedimento seguinte:

#### Informações e elementos de identificação do navio

A base de dados de navios do EMSWe deve verificar a conformidade dos dados recebidos das plataformas nacionais únicas para o setor marítimo de acordo com as definições e regras do conjunto de dados do EMSWe. Os dados não conformes são rejeitados pela base de dados de navios do EMSWe e a notificação do erro deve ser transmitida à plataforma nacional única para o setor marítimo em causa.

Se um registo de navio for aceite pela base de dados de navios do EMSWe, as informações e os elementos de identificação do navio existentes correspondentes deverão ser atualizados na base de dados de navios do EMSWe. Caso não exista um registo do navio correspondente, a base de dados de navios do EMSWe deverá criar um novo registo do navio. O registo do navio deve utilizar como identificador o número IMO do navio ou, em alternativa, o número MMSI e o indicativo de chamada. Se os identificadores não forem fornecidos, a base de dados de navios do EMSWe ignorará as informações recebidas e transmitirá uma mensagem de erro à plataforma nacional única para o setor marítimo em causa.

A base de dados de navios do EMSWe deve comparar os elementos de identificação do navio e os elementos de informação recebidos com os elementos dos dados existentes no registo do navio correspondente na base de dados de navios do EMSWe. A base de dados de navios do EMSWe deve atualizar cada elemento de dados que tenha recebido um valor diferente do valor constante da base de dados de navios do EMSWe. Os elementos de identificação do navio e os elementos de dados não recebidos devem ser mantidos sem alterações na base de dados dos navios do EMSWe.

Um registo de navios pode conter informações provenientes de diferentes declarantes.

#### Informações relativas à isenção de declaração de navios

A base de dados de navios do EMSWe deve extrair do SafeSeaNet todas as atualizações das informações de isenção de declaração de navios comunicadas pelos Estados-Membros.

| Prazos para a disponibilidade de dados: A base de dados de navios do EMSWe deve ser apoiada por ligações e redes de comunicação de dados que permitam transferir informações entre os dois sistemas no espaço de um minuto. |
|---|
| Prazos para o armazenamento de dados: A lista das informações e elementos de identificação dos navios e das isenções de declaração dos navios deve estar disponível na base de dados de navios do EMSWe sem qualquer limite de tempo. |
| Requisitos de disponibilidade do sistema: A base de dados de navios do EMSWe deve ser mantida em funcionamento a um mínimo de 99 % durante um período de um ano, sendo o período máximo admissível de interrupção de 12 horas. <br> As informações da base de dados de navios do EMSWe devem ser recuperáveis tanto quanto possível após um período de suspensão. <br> Os Estados-Membros devem ser informados em caso de falha ou interrupção programada. |

#### 5. Medidas mínimas de segurança do sistema

| Identificação: Deve ser implementado um mecanismo de identificação fiável para identificar de forma única os utilizadores da base de dados de navios do EMSWe com um identificador de utilizador único. |
|---|
| Autenticação: O processo de autenticação da interface sistema a sistema da base de dados de navios do EMSWe deve basear-se em métodos de autenticação reconhecidos através da implementação do SSL bidirecional. Para a interface de utilizador Web, os utilizadores devem autenticar-se com um conjunto de credenciais. |
| Autorização: Os utilizadores devem ser autorizados mediante a aplicação de medidas de controlo do acesso às interfaces da base de dados de navios do EMSWe. Todos os acessos devem ser registados. As autorizações devem ser revistas regularmente. |
| Rastreabilidade e responsabilização: A base de dados de navios do EMSWe deve assegurar a não rejeição das ações realizadas pelos utilizadores através das suas interfaces. Para o efeito, a base de dados de navios do EMSWe deve acompanhar todos os acessos, as ocorrências ou modificações dos seus dados. A identificação do utilizador, o marcador temporal e a ação realizada devem ser registados para cada evento. |
| Integridade: A base de dados de navios do EMSWe deve realizar verificações da integridade do sistema que evitem eventos maliciosos que possam comprometer as suas funcionalidades. |

Para o efeito, a base de dados comum de localizações deve permitir a rastreabilidade de todos os acessos, de todas as ocorrências e alterações dos seus dados. | Integridade: A base de dados comum de localizações deve realizar controlos da integridade do sistema que evitem eventos maliciosos que possam comprometer as suas funcionalidades. |

## ANEXO VII — ESPECIFICAÇÕES TÉCNICAS, NORMAS E PROCEDIMENTOS PARA A CRIAÇÃO DA BASE DE DADOS COMUM DE MATERIAIS PERIGOSOS (HAZMAT)

#### 1. Panorâmica da base de dados comum de materiais perigosos

A base de dados comum de materiais perigosos deve permitir a recolha, o armazenamento, a atualização e o fornecimento de informações sobre mercadorias perigosas e poluentes decorrentes das seguintes convenções e acordos, incluindo versões voluntárias (se for caso disso):

- — Código Marítimo Internacional para o Transporte de Mercadorias Perigosas (código IMDG),

- — Código Marítimo Internacional relativo a Cargas Sólidas a Granel (IMSBC);

- — Código internacional de construção e equipamento de navios de transporte de gases liquefeitos a granel (IGC);

- — Código internacional de construção e equipamento de navios de transporte de produtos químicos perigosos a granel (IBC);

- — Convenção Internacional para a Prevenção da Poluição por Navios (MARPOL, Anexo I);

- — Acordos tripartidos (MEPC.2/Circular).

A fim de assegurar o bom funcionamento e a disponibilidade das informações, a base de dados comum de materiais perigosos deve respeitar os requisitos mínimos de desempenho do sistema enumerados no ponto 4 e as medidas mínimas de segurança do sistema enumeradas no ponto 5.

A Comissão, assistida pela Agência Europeia da Segurança Marítima, deve:

- — assegurar a criação da base de dados comum de materiais perigosos, das suas interfaces, dos seus serviços e da gestão dos utilizadores;

- — assegurar que as plataformas nacionais únicas para o setor marítimo possam estabelecer a ligação à base de dados comum de materiais perigosos;

- — coordenar a execução dos ensaios de aceitação;

- — assegurar que a documentação operacional e técnica da base de dados comum de materiais perigosos seja disponibilizada aos coordenadores nacionais e atualizada.

#### 2. Interfaces da base de dados comum de materiais perigosos (Hazmat)

A base de dados comum de materiais perigosos deve fornecer informações sobre as mercadorias perigosas e poluentes através de uma interface sistema a sistema e de uma interface Web, tal como descritas nos pontos 2.1 e 2.2.

A Comissão, em consulta com os coordenadores nacionais, publica um Guia da Interface de Sistemas (SIG) que define o sistema de mensagens do sistema, as medidas e os procedimentos para estabelecer a ligação à base de dados comum de materiais perigosos, incluindo as políticas em matéria de direitos de acesso dos utilizadores e o processo de registo dos utilizadores.

#### 2.1. Interface sistema a sistema

A interface sistema a sistema deve estar à disposição das plataformas nacionais únicas para o intercâmbio automático de informações, utilizando um conjunto de mensagens predefinidas. A interface sistema a sistema deve suportar o serviço de anúncio descrito no ponto 2.1.1.

#### 2.1.1. Serviço de anúncio

A base de dados comum de materiais perigosos utiliza o serviço de anúncio para distribuir às plataformas nacionais únicas para o setor marítimo, que anteriormente subscreveram o serviço, os dados mais recentes na sequência de cada alteração (criação, atualização ou supressão) das informações sobre mercadorias perigosas e poluentes. A lista completa de informações sobre mercadorias perigosas e poluentes deve ser distribuída à plataforma nacional única para o setor marítimo aquando da subscrição do serviço.

#### 2.2. Interface Web

A interface Web deve ser acessível aos utilizadores autorizados para:

- — consultar a lista de mercadorias perigosas e poluentes;

- — consultar as informações da base de dados MAR-CIS sobre os perigos e riscos associados às mercadorias perigosas e poluentes;

- — descarregar a lista de mercadorias perigosas e poluentes com base em critérios diferentes e em formatos diferentes.

O acesso à interface Web da base de dados comum de materiais perigosos deve ser facultado aos coordenadores nacionais, mediante pedido.

#### 3. Procedimentos de atualização da base de dados comum de materiais perigosos

A base de dados comum de materiais perigosos deve ser atualizada por sincronização com:

- — a versão mais recente dos códigos e convenções da OMI (IMDG, IMSBC, IGC, IBC, anexo I da MARPOL), disponível em Rulecheck [^1];

- — a última lista de acordos tripartidos publicada (MEPC.2/Circular), excluindo os acordos tripartidos provisórios.

#### 4. Requisitos mínimos de desempenho do sistema

| Prazos para a disponibilidade de dados: A base de dados comum de materiais perigosos deve ser apoiada por ligações e redes de comunicação de dados que permitam transferir informações entre ambos os sistemas no espaço de um minuto. |
|---|
| Prazos para o armazenamento de dados: As informações sobre mercadorias perigosas e poluentes devem estar disponíveis na base de dados comum de materiais perigosos sem quaisquer limites de tempo. |
| Requisitos de disponibilidade do sistema: A base de dados comum de materiais perigosos deve ser mantida em funcionamento a um mínimo de 99 % durante um período de um ano, sendo o período máximo admissível de interrupção de 12 horas. <br> As informações da base de dados comum de materiais perigosos devem ser recuperáveis tanto quanto possível após um período de suspensão. <br> Os Estados-Membros devem ser informados em caso de falha ou interrupção programada. |

#### 5. Medidas mínimas de segurança do sistema

| Identificação: Deve ser implementado um mecanismo de identificação fiável para identificar de forma inequívoca os utilizadores da base de dados comum sobre os perigos com um identificador de utilizador único. |
|---|
| Autenticação: O processo de autenticação da interface sistema a sistema da base de dados comum de materiais perigosos deve basear-se em métodos de autenticação reconhecidos através da implementação do SSL bidirecional. Para a interface de utilizador Web, os utilizadores devem autenticar-se com um conjunto de credenciais. |
| Autorização: Os utilizadores devem ser autorizados mediante a aplicação de medidas de controlo do acesso às interfaces da base de dados comum de materiais perigosos. Todos os acessos devem ser registados. As autorizações devem ser revistas regularmente. |
| Rastreabilidade e responsabilização: A base de dados comum de materiais perigosos deve assegurar a não rejeição das ações realizadas pelos utilizadores através das suas interfaces. Para o efeito, a base de dados comum de materiais perigosos deve acompanhar todos os acessos, as ocorrências e as alterações dos seus dados. A identificação do utilizador, o marcador temporal e a ação realizada devem ser registados para cada evento. |
| Integridade: A base de dados comum de materiais perigosos deve realizar controlos da integridade do sistema que evitem eventos maliciosos que possam comprometer as suas funcionalidades. |

[^1]: http://www.emsa.europa.eu/rulecheck.html
